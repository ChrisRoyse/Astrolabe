# Astrolabe Agent Context

`CLAUDE.md` is the repository operating manual and must be read before doing any work. GitHub issues are the state of record.

The execution boundary is non-negotiable:

- Work only from the canonical checkout at `/Users/steveabbey/Documents/Astrolabe`.
- **`main` only.** Commit directly to `main`. Never create branches, Git worktrees, or shadow checkouts. The worktree-provisioning machinery and its admission protocol are retired.
- Produce build and FSV evidence natively on `aarch64-apple-darwin`. The Rust host and the static `libcbm.a` archive must share one ABI; on this machine both are arm64 Mach-O. There is no launcher, no wrapper script, and no bootstrap bundle — run `cargo build` directly from the canonical workspace.
- Native evidence requirement: a build for a different target exercises different code paths and does not satisfy a DoD on this host. Record the native execution context in the issue.
- **Cross-platform, macOS-first (owner directive, 2026-08-01 — supersedes the 2026-07-11 Windows-only directive):** ASTROLABE is cross-platform, and its primary evidence-bearing host is macOS on Apple Silicon. The former "Windows and no other system" scope directive is withdrawn in full, together with the `DEFERRED[ASTRO_PORT_PHASE]` doctrine that existed only to justify it. macOS FSV is first-class closure evidence. Windows and Linux remain supported targets — their platform branches stay in the tree and must not be deleted — but they no longer gate any DoD. Portability work is ordinary in-scope work, not a deferred final phase.
- **`target/` hygiene:** `target/` is multi-gigabyte disposable evidence scratch, never persistent state. Build, promote the binary you intend to exercise out of `target/`, capture the FSV readback, then `rm -rf target/` and verify absence — including on failure or interruption. Verify absence before every pause, stop, issue close, turn end, or handoff. There is no lock protocol, lease, ownership manifest, or reclaim procedure: one operator, one agent, so a plain delete by the process that created it is correct and sufficient.
- Keep repository-controlled outputs inside the workspace, normally in `target/`. Never stage or commit them.
- Both parent code trees are owned first-class source (owner directive 2026-07-12; EPIC #286): edit them directly with the normal quality bar. The legacy overlay + pin machinery was dismantled under #286; do not reintroduce it. `patches/cbm/` is not overlay machinery — it is Astrolabe-owned libcbm build glue compiled directly by `cbm-sys/build.rs`.
- **Security is a non-goal (owner directive 2026-07-25; #740):** this system runs locally, for one operator, on one machine. Never perform, plan, or file security work — no threat models, hardening, injection/supply-chain screening, sandboxing, secret scanning, egress restriction, privacy/compliance erasure, or CVE tracking — and never add security clauses to an issue Scope or DoD. Security findings are closed `not planned` citing #740; `area:security` is retired. Correctness is untouched: fail-closed refusals, labeled degradation, malformed-input validation, and drift/integrity codes all stay.
- **No CI/CD (banned, owner directive 2026-07-11):** GitHub Actions and all hosted CI/CD are banned. Never create `.github/` content, cite a CI job as coverage owner, or defer evidence "until CI runs." All verification is local full-state verification, recorded on the issue.
- **FSV-only verification (owner directive, 2026-07-13):** the gate/check suite, gate configs, suite-impact machinery, and gate self-tests are retired and deleted — do not rebuild them. Verification is Full State Verification against reality: build the real artifact natively, exercise the real behavior with real data (never mocks), independently read back the persisted state, probe the relevant edge cases, and record command + context + readback on the driving issue. **Manual FSV only — no tests (owner directive, 2026-07-14):** all test code was deleted from the repo (`#[cfg(test)]`, `tests/` dirs, the cbm C suite, trybuild, test scripts); passing tests prove nothing. Never write, run, or cite a test for verification, evidence, measurement, or closure. Verify by exercising the real artifact yourself against a real codebase and reading back persisted state by hand; measurements run against the real binary/server. `cargo check`/`cargo build` remain valid buildability evidence.
- **Smallest sufficient corpus:** prefer a synthetic fixture whose expected output you can state in advance (known symbols, known edges, known counts) over a large real corpus whose correct answer you cannot independently state. Scale up only when the property under test requires it.
- Make and execute the technical, environment/toolchain, prioritization, and implementation decisions needed to reach ASTROLABE's intended end state. Prefer the most robust, durable, project-aligned solution over a locally easier workaround; do not pause for routine choices or leave known next steps undecided.
- GitHub issues and their comments are the durable state record. At every resume or context compaction, re-read this file, `CLAUDE.md`, the active issue and its comments, and the current Git state before acting. A claimed or `status:in-progress` issue is still available to this sole agent.
- Treat a result as real only after direct state verification of the actual artifact, process, browser state, or persisted data. Record that evidence in the issue before closing it.
- Synapse provides full local perception and computer control and is the instrument of choice when an FSV needs to observe real UI or system state rather than a return value. Target a specific window; never synthesize input to whatever is frontmost. Use the already-open authenticated Chrome session through Synapse for browser work, opening only background tabs. Create and track a GitHub issue for every discovered problem outside the current fix.
- Rust formatter: `cargo fmt --all` runs normally on macOS.
- `calyx/` and `cbm/` (top-level, relocated out of `vendor/` in EPIC #286 Phase B) are ASTROLABE's own code, not upstream sources. No pins, no patch flow, no upstream tracking.
